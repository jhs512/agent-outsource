# 테스트 케이스

각 결과는 `local-skill-verification.md`에 모의/실제 구분과 근거를 기록한다. 실제 테스트는 별도 임시 작업 폴더의 짧은 텍스트/파일만 사용한다.

| ID | 경우 | 기대 결과 | 검증 방식 |
|---|---|---|---|
| T01 | Claude / agy 작업 전달·결과 | 제공자 세션과 결과 보존, 결과 없는 exit 0은 성공 아님 | 모의 + 각각 실제 |
| T02 | Codex 응답 종료 후 완료 통보 | caller thread에 짧은 이벤트, 모델 폴링 없음 | 실제 queue + 담당 대화 수신 |
| T03 | 완료 후 후속 질문 | 같은 provider session, 새 실행 시도 | 모의 + 각각 실제 |
| T04 | 중간 질문·실제 답·재개 | 질문 ID 검증, 임의 답 금지, live/종료 후 재개 구분 | 모의 + 각각 실제 |
| T05 | 필수 권한 우회·일반 질문 분리 | 양쪽 CLI 모든 경로에 bypass 플래그, 추가 승인 없음, 일반 질문은 답 대기 | 인자 조합 자동 검사 + 각각 실제 |
| T06 | 실행 중 취소 | 정확한 프로세스 트리 정리, cancelled, 결과/로그 보존 | 모의 + 각각 실제 |
| T07 | 실행파일 부재·비정상 종료 | failed + 원인 보존 + 알림 | 모의 |
| T08 | 긴 무출력 | 실행 유지, 프로그램 heartbeat, 모델 반복 조회 없음 | 모의 + 작은 실제 sleep |
| T09 | 동시 작업 라우팅 | job/session/caller 섞이지 않음 | 모의 + 실제 병렬 smoke |
| T10 | 알림 실패·재전송 | 결과 유지, 별도 outbox retry, 작업 중복 실행 없음 | 모의 |
| T11 | SQLite 여러 프로세스 쓰기 | WAL/busy 처리, 유일 키 보장 | 실제 다중 Node 프로세스 |
| T12 | daemon 중복 시작 | 한 소유자만 실행, 작업 단일 claim | 모의 통합 |
| T13 | daemon 비정상 종료·재시작 | PID/생성 시각 확인, 고아 정리 또는 명시적 중단, 자동 재실행 없음 | 모의 통합 |
| T14 | DB running인데 PID 없음 / 재사용 | 생존으로 오인하지 않음, 다른 프로세스 종료 금지 | 모의 |
| T15 | 전송 성공 직후 daemon 장애 | 같은 event ID 재전송 가능, ack/idempotency 기록 | 모의 |
| T16 | 같은 요청 동시 제출 | 동일 key 동일 작업, 다른 내용은 충돌 | 모의 + 다중 프로세스 |
| T17 | 같은 질문 중복·잘못된 답 | stale 요청 차단, 같은 답 idempotent, 다른 caller 거부 | 모의 |
| T18 | 로그 폭주/초대형 JSON | 메모리와 모델 출력 제한, 원본 로그 파일 유지 | 모의 |
| T19 | 작업 취소와 결과 경쟁 | terminal 상태 한 번, 결과/알림 일관성 | 모의 |
| T20 | 앱 종료/queue 연결 실패 | 알림 재시도·uncertain 보존, 완료 결과 유지 | 모의 실패; 실제 앱 종료는 미검증 |

추가 호환성: 이전 `options.permission: manual` 및 옵션 생략 요청도 반드시 bypass로 실행한다. 과거 idempotency key와 결과는 유지한다. Claude가 예외적으로 권한 control request를 보내도 원래 입력으로 자동 허용하며 질문 도구 요청은 자동 답변하지 않는다. 이전 수동 allow/deny 테스트 결과는 역사적 증거로만 보존한다.
