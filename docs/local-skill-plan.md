# 로컬 CLI 작업자 스킬 구현 계획

2026-09-23 확정 요구사항을 기준으로 작성한 당시 계획이다. 이전 JSON 파일 기반 초안은 보존한다. 최초 구현은 로컬 검증만 진행했으며, 이후 사용자 요청으로 설치 안내와 함께 공개 저장소에 반영했다.

추가 확정 요구: Claude Code와 Antigravity의 모든 실제 실행은 `--dangerously-skip-permissions`를 반드시 포함한다. 새 실행·세션 재개·질문 후 후속 실행에 동일하게 적용하며 선택 설정으로 제공하지 않는다. 일반 작업 질문은 실제 사용자 답을 기다린다. 아래 권한 요청 시험 중 수동 허용/거절은 이전 버전의 검증 이력이며 현재 동작은 자동 승인이다.

## 범위와 완료 기준

- Codex가 조율한다. 스킬은 호출자가 지정한 CLI·작업·대상 대화를 그대로 실행하고 결과를 운반한다. 배정 시점·작업 분할·모델 선택 정책은 사용자 프롬프트의 책임이다.
- 로컬 스킬 `cli-worker-bridge` 안에 외부 의존성 없는 Node.js 실행 프로그램을 둔다. 저장소에서 검증한 후 사용자 Codex skills 폴더에 설치한다.
- 홈 루트 `~/ai-oc.sqlite` 하나에 모든 프로젝트의 작업, 실행 시도, 세션, 질문/승인 요청, 답, 결과, 알림 outbox를 저장한다. 원본 대용량 로그는 별도 로컬 파일이다.
- WAL, busy timeout, 짧은 BEGIN IMMEDIATE 트랜잭션과 유일 키/조건부 변경으로 동시 호출·중복 실행을 제어한다.
- 백그라운드 Node 서비스가 CLI 프로세스와 알림을 관리한다. 모델의 반복 조회는 필요 없다. 호출자 thread ID를 매 요청에 받고 `codex queue --thread ... --message ...`로 통보한다.
- 작업 성공과 프로세스 종료를 구분한다. 작업 상태와 알림 상태도 별도이다. 알림 실패로 결과를 지우거나 작업을 다시 실행하지 않는다.

## 순서

1. 계획·테스트 케이스 작성. 설치된 CLI 도움말과 실제 소규모 프로토콜 실험으로 입력/응답/질문/권한 이벤트를 확인한다.
2. SQLite 저장소, 실행 임대/프로세스 식별, 영구 outbox 구현. 장애 뒤 자동 작업 재실행 대신 불확실한 실행을 interrupted/needs_review로 보존한다.
3. Claude/agy 어댑터 구현. 실제 제어 요청은 가능한 경우 살아 있는 stdin에 답한다. 종료 후 질문은 session ID로 재개한다. 미지원 동작은 명시한다.
4. CLI 명령과 스킬 문서 작성. 결과·로그 조회량 제한, 질문 ID와 실제 사용자 답, 권한 허용/거절 분리.
5. 모의 장애/동시성 테스트와 각 실제 CLI 스모크. `codex queue` 지연 전달 결과는 호출자 대화에 실제 도착한 증거와 연결한다.
6. 로컬 설치, 검증 보고. 실제 검증 성공·실패·미검증을 분리하고 원래 조율 대화로 보고한다.

## 핵심 불변식

- idempotency key는 호출자 대화 안에서 유일하며 내용이 다르면 재사용을 거부한다.
- 한 작업에는 한 활성 실행만 존재한다. 소유 프로세스 PID와 생성 시각을 확인하고 DB의 running 표시만으로 생존을 판정하지 않는다.
- 죽은 감독 프로세스의 실행은 무조건 재시도하지 않는다. 살아 있는 고아 작업자는 정확한 프로세스 식별을 검증해 정리하고 중단 상태를 보존한다.
- 결과 저장과 알림 생성은 같은 트랜잭션이다. 알림은 이벤트 ID를 포함한다. 전달 후 DB 기록 전 장애는 중복 수신 가능성이 있으므로 at-least-once 및 수신측 ack로 다룬다.
- 알림은 원래 caller thread로만 라우팅한다. 제공자의 session ID와 Codex thread ID를 혼동하지 않는다.
- 취소는 프로세스 트리 종료를 요청한 뒤 종료 관찰로 확정한다. 장시간 무출력은 실패 근거가 아니다.
- 원본 로그 전체를 모델로 반환하지 않는다. 짧은 요약과 결과 위치만 알리고 필요할 때 제한된 로그를 조회한다.
